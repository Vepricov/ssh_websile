# Новый сервер (BrainLab)

## Подключение

Персональную команду SSH, логин и пароль показывает `@brainlab_server_access_bot` в разделе «Мои серверы».

На сервере установлены четыре NVIDIA A100 80 GB. Перед запуском проверьте карты:

```bash
nvidia-smi
nvtop
```

Выберите конкретную карту:

```bash
CUDA_DEVICE_ORDER=PCI_BUS_ID CUDA_VISIBLE_DEVICES=0 python train.py
```

Для длительной работы создайте `tmux`-сессию:

```bash
tmux new -s experiment
```

## Файлы

- Личный код, окружения и результаты храните в `$HOME`.
- Перед загрузкой большого датасета проверьте свободное место через `df -h / /home`.
- Не записывайте большие файлы в системный `/tmp` без проверки его расположения и свободного места.

## mlsub / Cloud.ru

`mlsub` не включается вместе с аккаунтом BrainLab. Сначала получите доступ к BrainLab, затем отправьте отдельную заявку на `mlsub` в Telegram-боте. Доступ включается только после одобрения администратора. После добавления в группу откройте новую SSH-сессию.

`mlsub` отправляет задачи в общую очередь Cloud.ru. Личный аккаунт Cloud.ru и его API keys пользователю не нужны.

### Подготовка задачи

Код должен находиться в доступном по HTTPS Git-репозитории. Укажите entrypoint и, если нужно, `requirements.txt`. Сначала выполните dry run:

```bash
mlsub run \
  --repo https://github.com/org/repo \
  --entry train.py \
  --gpus 1 \
  --dry-run
```

После проверки отправьте задачу:

```bash
mlsub run \
  --repo https://github.com/org/repo \
  --entry train.py \
  --gpus 1
```

Дополнительные параметры:

```bash
mlsub run --repo <https-git> --branch <branch> --entry <file> \
  --gpus 1 --args "<arguments>" --env NAME=value --no-pip
```

### Управление очередью

```bash
mlsub list
mlsub status <job_name>
mlsub logs <job_name>
mlsub kill <job_name>
```

### Правила mlsub

- Обычно выбирайте одну или две GPU. Заявки на четыре и восемь GPU могут долго ждать свободную цельную ноду.
- Не отправляйте много одинаковых задач без необходимости. Ресурсы оплачивает внешний проект.
- Кеши и результаты, которые должны пережить задачу, сохраняйте в `/home/jovyan` внутри Cloud.ru job.
- Файловая система самой задачи временная. Не оставляйте единственную копию результата вне постоянного каталога.
- Используйте только образы, разрешённые текущей политикой `mlsub`.
- Если задача больше не нужна, завершите её через `mlsub kill <job_name>`.
- Если запуск падает без понятного сообщения, проверьте `mlsub status` и `mlsub logs` перед повторной отправкой.
