Подключение к SSH-серверу

Полное руководство по настройке безопасного и удобного подключения к серверу

Для эффективной и безопасной работы с нашим SSH-сервером, важно понимать, как правильно устанавливать соединение и управлять им. В этом разделе мы подробно рассмотрим процесс подключения, генерации SSH-ключей и настройки конфигурации SSH для вашего удобства.

1. Базовое подключение по SSH

Для первого подключения к серверу вам потребуется использовать команду ssh в вашем терминале. Эта команда позволяет установить защищенное соединение с удаленным сервером.

Формат команды:

ssh -p [порт] [имя_пользователя]@[адрес_сервера]

Пример для наших серверов:

# Старый сервер (x4 RTX 2080 11гб, x2 A100 40гб, x2 A100 80гб)
ssh -p 10096 username@proxy2.cod.phystech.edu

# Новый сервер (x4 A100 80гб)
ssh -p 10210 username@proxy2.cod.phystech.edu

Где username — это ваше имя пользователя на сервере. После выполнения этой команды система запросит ваш пароль. Введите его, чтобы установить соединение.

Важно: При первом подключении система может запросить подтверждение подлинности сервера. Введите yes для продолжения.

2. Генерация SSH-ключей для беспарольного доступа

Ввод пароля при каждом подключении может быть неудобным и отнимать время. Для повышения удобства и безопасности рекомендуется использовать пару SSH-ключей: приватный (private key) и публичный (public key). Приватный ключ хранится на вашем локальном компьютере и должен быть строго конфиденциальным. Публичный ключ размещается на сервере.

Шаг 1: Генерация пары ключей

Вы можете сгенерировать пару SSH-ключей с помощью команды ssh-keygen. Рекомендуется использовать алгоритм ed25519 для лучшей безопасности. 

ssh-keygen -t ed25519 -f ~/.ssh/opt_mipt

Эта команда создаст два файла в директории ~/.ssh на вашем локальном компьютере:

  • opt_mipt (ваш приватный ключ)
  • opt_mipt.pub (ваш публичный ключ)

Совет: При генерации ключей система может предложить ввести пароль для дополнительной защиты приватного ключа. Это необязательно, но рекомендуется для повышения безопасности.

Шаг 2: Копирование публичного ключа на сервер

После генерации ключей вам необходимо скопировать публичный ключ (opt_mipt.pub) на сервер. Это можно сделать с помощью утилиты ssh-copy-id: 

ssh-copy-id -i ~/.ssh/opt_mipt -p [10096 или 10210] username@proxy2.cod.phystech.edu

Эта команда автоматически добавит содержимое вашего публичного ключа в файл ~/.ssh/authorized_keys на сервере. После успешного выполнения этой команды вы сможете подключаться к серверу без ввода пароля, используя вашу пару SSH-ключей.

Альтернативный способ копирования ключа:

Если ssh-copy-id недоступен, вы можете скопировать ключ вручную: 

# Показать содержимое публичного ключа
cat ~/.ssh/opt_mipt.pub

# Подключиться к серверу и добавить ключ в authorized_keys
ssh -p [10096 или 10210] username@proxy2.cod.phystech.edu
mkdir -p ~/.ssh
echo "ваш_публичный_ключ" >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
chmod 700 ~/.ssh

3. Настройка SSH Config для упрощенного подключения

Чтобы еще больше упростить процесс подключения и избежать необходимости каждый раз вводить полный адрес и порт, вы можете настроить файл конфигурации SSH на вашем локальном компьютере (~/.ssh/config).

Пример настройки:

Откройте или создайте файл ~/.ssh/config в вашем любимом текстовом редакторе и добавьте следующие строки: 

Host opt
  User username
  HostName proxy2.cod.phystech.edu
  Port [10096 или 10210]
  IdentityFile ~/.ssh/opt_mipt

Пояснения параметров:

  • Host opt: Это короткое имя (алиас), которое вы будете использовать для подключения. Вы можете выбрать любое удобное для вас имя.
  • User username: Ваше имя пользователя на SSH-сервере.
  • HostName proxy2.cod.phystech.edu: Полный адрес SSH-сервера.
  • Port [10096 или 10210]: Порт, используемый для SSH-соединения.
  • IdentityFile ~/.ssh/opt_mipt: Путь к вашему приватному ключу на локальном компьютере.

Использование настроенного подключения:

Теперь для подключения к серверу вам достаточно ввести: 

ssh opt

Это значительно упрощает процесс и делает его более удобным.

4. Дополнительные настройки SSH Config

Вы можете добавить дополнительные параметры в ваш SSH config для еще большего удобства: 

Host opt
  User username
  HostName proxy2.cod.phystech.edu
  Port [10096 или 10210]
  IdentityFile ~/.ssh/opt_mipt
  ServerAliveInterval 60
  ServerAliveCountMax 3
  TCPKeepAlive yes
  Compression yes

Дополнительные параметры:

  • ServerAliveInterval 60: Отправляет keep-alive сообщения каждые 60 секунд
  • ServerAliveCountMax 3: Максимальное количество неотвеченных keep-alive сообщений
  • TCPKeepAlive yes: Включает TCP keep-alive
  • Compression yes: Включает сжатие данных

5. Устранение неполадок (Troubleshooting)

Если у вас возникли проблемы с подключением, проверьте следующее:

Проблемы с аутентификацией:

  • Правильность имени пользователя и пароля: Убедитесь, что вы используете правильные учетные данные.
  • Права доступа к ключам: Убедитесь, что права доступа к вашим приватным ключам установлены корректно: 
chmod 600 ~/.ssh/opt_mipt
chmod 700 ~/.ssh

Проблемы с подключением:

  • Доступность сервера: Проверьте, что сервер доступен и не заблокирован фаерволом.
  • Правильность порта: Убедитесь, что используете правильный порт (10096 или 10210).

Отладка SSH:

Для получения подробной информации о процессе подключения используйте флаг -v: 

ssh -v -p [10096 или 10210] username@proxy2.cod.phystech.edu

Для еще более подробной информации используйте -vv или -vvv.

Проверка содержимого authorized_keys:

На сервере проверьте, что ваш публичный ключ корректно добавлен: 

cat ~/.ssh/authorized_keys

Если проблемы сохраняются: Напишите ошибку в чат сервера с указанием вашего имени пользователя с описанием проблемы и сообщениями об ошибках.

6. Безопасность SSH

Лучшие практики:

  • Никогда не делитесь приватным ключом: Ваш приватный ключ должен оставаться только на вашем компьютере.
  • Используйте пароль для приватного ключа: Это добавляет дополнительный уровень защиты.
  • Регулярно обновляйте ключи: Рекомендуется обновлять SSH-ключи каждые 1-2 года.
  • Отключайте неиспользуемые ключи: Удаляйте старые ключи из authorized_keys на сервере.
  • Используйте разные ключи для разных серверов: Не используйте один ключ для всех серверов.

who
